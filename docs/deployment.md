# Hosted deployment

The repository includes a Render Blueprint in `render.yaml`. It builds the production Docker target, attaches a 1 GB persistent disk at `/var/data`, stores one SQLite workspace per verified Google account, sets `/healthz` as the health check, and keeps the service on one instance. The disk is required: Render's ordinary filesystem is ephemeral, and its disks are available on paid services and cannot be shared across multiple instances. See [Render Docker deployment](https://render.com/docs/docker), [persistent disks](https://render.com/docs/disks), and [pricing](https://render.com/pricing).

The selected Render Starter web service is currently listed at $7/month. A 1 GB disk at $0.25/GB/month makes the baseline about $7.25/month, before taxes or usage outside included limits. Verify the dashboard total before creating the service; Render prorates compute and may charge for extra bandwidth. The user has authorized a paid hosting setup.

## Before creating the service

1. Create a development Google Cloud OAuth **Web application** client for local use with redirect `http://127.0.0.1:8080/auth/google/callback`. Google recommends separate Cloud projects for development and production. For public production sign-in, use a domain you own and can verify; Google's production OAuth guidance requires verification of domains associated with the app homepage and OAuth redirect URIs. A shared `onrender.com` subdomain may not satisfy this ownership requirement. See [Google OAuth production readiness](https://developers.google.com/identity/protocols/oauth2/production-readiness/policy-compliance).
2. Create or use a production homepage on that owned domain and publish a privacy policy URL there. Configure Google Auth Platform Branding and Audience for external visitors. Use a production OAuth Web application client with redirect URI `https://<your-owned-domain>/auth/google/callback`. This app requests only `openid email profile`; do not add unrelated Google API scopes.
3. Keep the sandbox Airwallex Client ID and scoped API key available. These go into Render's service environment variables, not GitHub or the browser.
4. The repository has been pushed to `https://github.com/demonchant/adaptive-treasure-controller.git`, branch `main`. `.env`, `.data`, workspace databases, test results, and Playwright reports are ignored.
5. In Render, create a Blueprint instance from that repository using `render.yaml`. Choose the paid Starter plan and Frankfurt region. Enter Airwallex and production Google OAuth secrets in the Blueprint's prompted secret fields. Do not bulk-import the local `.env`; enter the secret keys individually so local URL and cookie settings do not overwrite the hosted configuration.

Render provides the service's HTTPS URL as `RENDER_EXTERNAL_URL`; the app uses it as the fallback origin. Add the owned domain to the Render service, configure the DNS records Render displays, and wait for TLS/domain verification. Then configure the production Google OAuth redirect URI to exactly `https://<your-owned-domain>/auth/google/callback`. Render's docs describe generated URLs, custom domains, and secret environment variables: [default environment variables](https://render.com/docs/environment-variables), [custom domains](https://render.com/docs/custom-domains), and [environment variables and secrets](https://render.com/docs/configure-environment-variables).

After deployment, visit `/healthz`, then open the root URL and sign in with Google. Verify that separate Google accounts see empty, independent workspaces. Refresh a sandbox balance and run the read-only workflow first. Do not execute a sandbox transfer as part of deployment verification; it needs separate explicit approval.

## Deployment boundary

Google identities and local app data are isolated per visitor, but every visitor uses the same server-side Airwallex sandbox key/account. Their sandbox balance is shared. The app serializes transfer attempts in one server process and refreshes the provider balance before execution. Do not scale this SQLite-backed service to multiple instances. The repository is connected to GitHub; a public app URL still requires the user to configure OAuth, a verifiable domain, and the Render Blueprint in their account dashboards.
